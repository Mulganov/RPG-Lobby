# RPG-Lobby

Лобби для Paper 26.2 и Java 25. При запуске создаёт платформу в пустом мире. После входа открывает меню режимов. Каждый игровой сервер остаётся отдельным процессом Minecraft.

## Развёртывание

1. Обнови Cloud и примени миграции для авторизации лобби. В `GAME_SERVER_TOKENS_JSON` создай отдельный идентификатор для лобби со scope `lobby`. Токен положи в `LOBBY_CLOUD_TOKEN` на VPS. Для игровых серверов со старыми токенами из переменной окружения добавь scope `lobby_transfer` к их существующим правам. Учётные данные игровых серверов, выпущенные Cloud, получают это право после обновления.
2. Скачай исходники нужного коммита из GitHub. Скопируй `.env.example` в `.env`, укажи HTTPS-адрес Cloud, ID лобби и токен. Поставь `EULA=TRUE`, если согласен с условиями Minecraft. Если текущий сервер занимает порт 25565, выбери другой `LOBBY_BIND_PORT`.
3. Запусти `docker compose up -d --build`. Docker соберёт JAR из исходников и запустит Paper. Логи доступны через `docker compose logs -f lobby`.
4. В Cloud → «Подключение из лобби» проверь окружение и ID игрового сервера в Game API, если он отличается от ID в Cloud. Core передаёт порт, а Cloud берёт публичный IP из отчёта аналитики. Поля адреса и порта в Cloud переопределяют автоматический адрес, если сервер работает за NAT, прокси или отдельным доменом. Чтобы отключить вход, очисти ручной адрес и сними «Определять адрес автоматически». При смене каталога исходников сохрани прежний `LOBBY_DATA_DIR` и используй тот же Compose project name.
5. Обнови RPG-Core на игровых серверах. После проверки лобби задай им `RPG_LOBBY_HOST` и `RPG_LOBBY_PORT`, установи `accepts-transfers=true` в `server.properties` и перезапусти. Для режима с существующими offline-аккаунтами задай одинаковый режим идентификации на всех инстансах и проверь UUID тестового аккаунта до переключения публичного входа.

Если на игровом сервере остались аккаунты, которые ещё лежат только в старых локальных файлах, перенеси их в Cloud до переключения входа на лобби.

В стандартном offline-режиме Paper 26.2 игровой транспорт не шифруется. HTTPS в `LOBBY_CLOUD_URL` защищает соединение лобби с Cloud. Для публичного ввода действующих паролей нужен защищённый вход игрока, например через HTTPS-страницу Cloud. Текущий вход через игровой чат подходит для закрытой проверки с тестовыми аккаунтами.

## Проверка

Зайди на лобби существующим аккаунтом и открой `/modes`. Лобби загружает доступность серверов, число игроков и разрешения из Cloud при каждом открытии меню. В DEV могут войти администраторы и альфа-тестеры, в TEST также бета-тестеры. PROD открыт всем игрокам.

Выбери режим и вернись через `/hub`. Проверь прямой вход на игровой сервер и повторный вход после отключения клиента. На игровых серверах проверь, что прежние данные игрока доступны под тем же аккаунтом.

## Сборка

`gradle build` с JDK 25 и Gradle 9.4.1. Для установки используется `docker compose up -d --build` из репозитория.
